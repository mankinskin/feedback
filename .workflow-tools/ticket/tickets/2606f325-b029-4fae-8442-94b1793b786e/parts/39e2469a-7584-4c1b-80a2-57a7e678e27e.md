## Follow-up: install-mode selection (prompt / flag) with abort-vs-warn semantics

Per additional user feedback, `tools/install/sync-copilot-surfaces.sh` was extended:

- New `--mode=auto|symlink|copy` flag (default `auto`).
- When invoked with no `--mode` on an interactive terminal (stdin+stdout are
  a tty), the script now prompts the user to choose 1) symlink, 2) copy, or
  3) auto, before doing anything.
- Non-interactive callers (bootstrap.sh -> init.sh) never hang: with no
  `--mode` and no tty, it silently defaults to `--mode=auto`. `init.sh` was
  updated to pass `--mode=auto` explicitly for clarity.
- `--mode=symlink` (explicit request): if a real symlink cannot be created
  for any of the three directories, the whole script **aborts** (exit 1)
  with a clear message instead of silently falling back.
- `--mode=auto` (default): unchanged fallback-to-read-only-copy behavior,
  but the message is now an explicit `WARNING —` line on stderr instead of
  a plain informational printf.
- `--mode=copy` (explicit request): skips the symlink attempt entirely and
  goes straight to the read-only copy, no warning printed (that's the
  expected/requested behavior).

Validated on this host (no Windows Developer Mode/elevation available):
- `--help` prints usage.
- `--mode=auto` -> WARNING + read-only copy for all three dirs, exit 0.
- `--mode=symlink` -> ABORT message + exit 1 (correctly detected via `-L && -d` check).
- `--mode=copy` -> read-only copy, no warning, exit 0.
- `--mode=bogus` -> rejected with usage, exit 2.
- No-flag + `< /dev/null` (non-interactive) -> defaults to auto with a note, exit 0, does not hang.

Symlink-success path still not exercised live on this host (same limitation
noted in the original review part) since Developer Mode/elevation isn't
available here.
